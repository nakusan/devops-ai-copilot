# 6.9 Web 前端模块

> 所属系统：DevOps AI Copilot — 客户端（Web UI）  
> 模块定位：**极简对话式操作界面** — 参照 DeepSeek 等主流 AI 对话产品的交互范式，对接控制面 `/api/v1/**` 公开 API，覆盖登录、多轮对话、文件上传与任务状态查看  
> 设计原则：界面干净、操作少、只做基本能力，不追求视觉打磨

---

## 1. 功能背景与边界

### 1.1 功能背景

DevOps AI Copilot 的后端已具备完整能力：JWT 鉴权、会话与消息管理、SSE 流式聊天、知识库文档入库、大文件异步分析等。研发人员需要一个**低学习成本**的 Web 界面来使用这些能力，而不是手工拼装 HTTP 请求。

目标体验：

- **以对话为中心**：用户打开页面即可提问，助手回复逐字流出（SSE）。
- **文件即附件**：在输入框旁上传文档或日志，后台异步处理后，用户继续在对话中自然语言追问。
- **历史可回溯**：左侧展示会话列表，点击即可切换并加载历史消息。

交互参照 DeepSeek 式布局：左侧窄栏（导航 + 历史），右侧宽栏（消息区 + 底部输入框），留白充足、无多余面板。

### 1.2 模块职责（In Scope）

| 能力 | 说明 |
|------|------|
| 用户认证 | 注册、登录、Token 存储与静默刷新 |
| 会话管理 | 新建、列表、切换、改标题、归档删除 |
| 流式对话 | 发送消息、接收 SSE `token`/`done`/`error`/`citation` |
| 历史消息 | 切换会话时拉取分页消息并渲染 |
| 知识库上传 | `multipart/form-data` 上传 pdf/md/txt，轮询入库状态 |
| 分析任务上传 | 上传 log/txt/hprof，轮询分析状态，展示 `resultSummary` |
| 文件列表 | 侧边栏查看知识库文档与分析任务历史 |
| Agent 只读 | 新建会话时获取 Agent 列表（默认使用种子 Agent `id=1`） |
| 错误展示 | 统一解析 `{ code, message, traceId }` 并提示用户 |

### 1.3 模块边界（Out of Scope）

| 不属于本模块 | 说明 |
|--------------|------|
| `/internal/**` 接口 | 服务间调用，不对浏览器暴露 |
| 向量检索、LangGraph、MCP 执行 | 后端 Python 智能面职责 |
| 文件解析、Embedding、Heap 分析算法 | 后端异步 Worker |
| Markdown / 代码高亮渲染 | MVP 用纯文本；V2 可选 |
| 深色模式、国际化、移动端适配 | V2 |
| WebSocket 推送任务进度 | MVP 用轮询；足够简单 |
| Admin Agent CRUD 完整表单 | MVP 可隐藏或极简；需 `ADMIN` 角色 |
| 预签名直传 MinIO | 后端 V1 能力；MVP 走服务端 multipart 上传 |

### 2.2 区域说明

| 区域 | 宽度 | 内容 |
|------|------|------|

| **主区** | 弹性剩余 | 消息列表（居中，最大宽度 ~720px）、底部固定输入框 |
| **输入框** | 全宽圆角容器 | 多行文本、📎 附件按钮、圆形发送按钮（↑） |

### 2.3 视觉规范（MVP）

| 元素 | 规范 |
|------|------|
| 背景 | 主区 `#ffffff`，侧栏 `#f7f7f8` |

| 圆角 | 输入框、按钮 `12px~16px` |
| 字体 | 系统 sans-serif 栈，不引入 Web Font |
| 图标 | Unicode 或内联 SVG，不引入图标库 |
| 消息气泡 | 用户右对齐或浅蓝底；助手左对齐或无边框纯文本 |

### 2.4 空态与加载态

- **未登录**：侧栏底部或全屏轻量表单（用户名 + 密码 + 登录/注册 Tab）。
- **已登录无会话**：主区居中「开始对话」+ 输入框可用；发送首条消息时自动创建 Session。
- **切换会话**：主区显示 skeleton 或「加载中...」，消息加载完成后滚动到底部。
- **流式回复**：助手消息区末尾显示闪烁光标或「...」直至 `done`。

## 3. 用户操作流程

### 3.1 主流程：对话

```text
打开页面
  → 登录（或注册）
  → 点击「新对话」或直接在输入框提问
  → POST /sessions 创建 Session（agentId 默认 1）
  → 输入问题 → 发送
  → POST /sessions/{id}/chat（SSE）
  → 逐字渲染助手回复
  → 同 Session 内继续追问
  → 侧栏点击历史 Session 切换
```

### 3.2 文件流程：上传后在对话中提问

后端设计为 **上传与聊天解耦**：文件先异步处理，用户在对话中用自然语言引用（RAG 检索知识库、Agent 查询分析摘要）。

```text
点击 📎 选择文件
  → 前端按扩展名路由上传接口（见 §5.2）
  → 202 响应，对话区插入系统消息「xxx 已提交，处理中...」
  → 轮询 GET 详情接口直至 COMPLETED / FAILED
  → 更新系统消息状态
  → 用户输入「总结一下刚上传的日志」→ 正常 SSE 对话
```

### 3.3 侧栏「文件」面板

```text
点击「文件」
  → Tab：知识库 | 分析任务
  → GET 分页列表
  → 展示 title/status/时间；分析任务 COMPLETED 时展示 resultSummary 摘要
```

## 4. API 对接清单

前端仅调用控制面 **`/api/v1/**`** 公开 API（默认 `http://localhost:8080`）。

### 4.1 认证（6.1）

| 方法 | 路径 | 请求体 | 响应 |
|------|------|--------|------|
| POST | `/auth/register` | `{ username, password }` | `TokenPair` |
| POST | `/auth/login` | `{ username, password }` | `TokenPair` |
| POST | `/auth/refresh` | `{ refreshToken }` | `TokenPair` |

`TokenPair`：`{ accessToken, refreshToken, expiresInSeconds }`

**Token 策略：**

- `accessToken`、`refreshToken` 存 `localStorage`。
- 普通请求 Header：`Authorization: Bearer {accessToken}`。
- 收到 401 时尝试 `refresh`，成功后重试原请求；refresh 失败则跳转登录。
- SSE 连接建立时校验 JWT 一次；连接存续期间不因 Access 15min 过期中断（见 6.2 设计）。新开会话须携带有效 Token。

### 4.2 Agent（6.2）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/agents` | Bearer | 列表；新建 Session 时选用 |
| GET | `/agents/{id}` | Bearer | 详情 |
| POST | `/agents` | Bearer + ADMIN | MVP 可不做 UI |
| PUT | `/agents/{id}` | Bearer + ADMIN | MVP 可不做 UI |
| DELETE | `/agents/{id}` | Bearer + ADMIN | MVP 可不做 UI |

新建会话默认 `{ "agentId": 1, "title": "新对话" }`（种子数据见 `deploy/postgres/10_seed_agent.sql`）。

### 4.3 会话与消息（6.2）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/sessions` | 创建；body: `{ agentId, title? }` |
| GET | `/sessions` | 当前用户会话列表 |
| GET | `/sessions/{id}` | 会话详情 |
| PATCH | `/sessions/{id}` | 更新 `{ title?, status? }`；`status=ARCHIVED` 归档 |
| DELETE | `/sessions/{id}` | 归档（204） |
| GET | `/sessions/{sessionId}/messages?page=1&size=20` | 历史消息分页 |
| POST | `/sessions/{sessionId}/chat` | SSE 流式聊天；body: `{ content, clientMessageId? }` |

**SSE 事件格式**（`Content-Type: text/event-stream`）：

```text
event: token
data: {"text":"根据"}

event: citation
data: {"chunks":[{"docTitle":"状态码字典","chunkId":"..."}]}

event: done
data: {"messageId":"...","usage":{"promptTokens":120,"completionTokens":80}}

event: error
data: {"code":"LLM_TIMEOUT","message":"..."}
```

前端处理：

| 事件 | 行为 |
|------|------|
| `token` | 追加 `data.text` 到当前助手消息 |
| `citation` | MVP：消息下方一行小字展示引用来源；或忽略 |
| `done` | 结束流式，移除 loading 态 |
| `error` | 展示错误，结束流式 |

SSE 须用 `fetch` + `ReadableStream` 解析（POST 请求无法使用原生 `EventSource`）。

### 4.4 知识库（6.3）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/knowledge/documents` | `multipart/form-data`：`file`（必填），`title`（可选）；**202** |
| GET | `/knowledge/documents/{id}` | 文档状态 |
| GET | `/knowledge/documents?page=1&size=20` | 分页列表 |

响应示例：

```json
// POST 202
{ "documentId": "uuid", "jobId": "uuid", "status": "PENDING" }

// GET 详情
{
  "documentId": "uuid",
  "title": "状态码手册.pdf",
  "mimeType": "application/pdf",
  "sizeBytes": 1024000,
  "status": "COMPLETED",
  "errorMessage": null,
  "createdAt": "...",
  "updatedAt": "..."
}
```

**约束：** 扩展名 `pdf` / `md` / `txt`；单文件 ≤ 20MB。

### 4.5 分析任务（6.3 / 6.8）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/analysis/jobs` | `multipart/form-data`：`file`（必填），`fileType`（可选：`HEAP_DUMP` / `GC_LOG` / `APP_LOG`）；**202** |
| GET | `/analysis/jobs/{id}` | 任务状态与结果 |
| GET | `/analysis/jobs?page=1&size=20` | 分页列表 |

响应示例：

```json
// POST 202
{ "jobId": "uuid", "fileType": "APP_LOG", "status": "PENDING", ... }

// GET 详情（COMPLETED）
{
  "jobId": "uuid",
  "fileType": "APP_LOG",
  "status": "COMPLETED",
  "resultSummary": "发现 3 处 OOM 相关堆栈...",
  "errorMessage": null,
  "createdAt": "...",
  "updatedAt": "..."
}
```

**约束：** 扩展名 `log` / `txt` / `hprof`；单文件 ≤ 100MB。未传 `fileType` 时后端按扩展名推断（`hprof→HEAP_DUMP`，其余→`APP_LOG`）。

### 4.6 任务状态枚举

`PENDING → PROCESSING → COMPLETED | FAILED`（与 6.3 `JobStatus` 一致）。

## 5. 文件上传设计

### 5.1 交互入口

- 输入框左下角 **📎** 按钮，触发隐藏 `<input type="file">`。
- 选中文件后在输入框上方显示文件名 Chip，可取消。
- 上传进行中禁用发送按钮，防止重复提交。

### 5.2 扩展名路由

| 扩展名 | 目标接口 | 说明 |
|--------|----------|------|
| `.pdf`, `.md` | `POST /knowledge/documents` | 知识库入库 |
| `.hprof`, `.log` | `POST /analysis/jobs` | 分析任务 |
| `.txt` | **用户二选一** | 弹轻量选择：「入库知识库」/「提交分析」 |

`.txt` 同时被两类接口接受，须让用户明确意图，避免误路由。

### 5.3 上传实现要点

```javascript
const form = new FormData();
form.append('file', file);
form.append('title', file.name); // 知识库可选

await fetch('/api/v1/knowledge/documents', {
  method: 'POST',
  headers: { Authorization: `Bearer ${accessToken}` },
  body: form,
  // 禁止手动设置 Content-Type，由浏览器附加 boundary
});
```

### 5.4 异步状态轮询

上传返回 202 后立即在对话区插入**系统消息**（非 user/assistant 角色，前端本地渲染）：

```text
📄 app.log 已提交分析，处理中...
```

轮询策略：

| 状态 | 间隔 | 动作 |
|------|------|------|
| `PENDING` | 2s | 继续轮询 |
| `PROCESSING` | 3s | 继续轮询 |
| `COMPLETED` | — | 更新为「✅ 已完成，可在对话中提问」 |
| `FAILED` | — | 展示 `errorMessage` |

轮询上限建议 60 次（约 2~3 分钟），超时提示「处理时间较长，请在文件列表中查看」。

知识库轮询：`GET /knowledge/documents/{documentId}`  
分析任务轮询：`GET /analysis/jobs/{jobId}`

### 5.5 上传限流

后端按用户每小时最多 10 次上传（6.3）。超限返回 `429 RATE_LIMITED`，前端展示 `message` 即可。

### 6.3 统一 API 封装

```javascript
async function api(path, options = {}) {
  const isForm = options.body instanceof FormData;
  const res = await fetch('/api/v1' + path, {
    ...options,
    headers: {
      ...(isForm ? {} : { 'Content-Type': 'application/json' }),
      Authorization: `Bearer ${getAccessToken()}`,
      ...options.headers,
    },
  });
  if (res.status === 401) {
    const refreshed = await tryRefreshToken();
    if (refreshed) return api(path, options);
    redirectToLogin();
    throw new Error('未登录');
  }
  if (!res.ok) {
    const err = await res.json(); // ErrorResponse
    throw err;
  }
  return res.status === 204 ? null : res.json();
}
```

### 6.4 SSE 解析要点

```javascript
async function streamChat(sessionId, content, onToken, onDone, onError) {
  const res = await fetch(`/api/v1/sessions/${sessionId}/chat`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${getAccessToken()}`,
    },
    body: JSON.stringify({
      content,
      clientMessageId: `msg-${Date.now()}`,
    }),
  });

  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const blocks = buffer.split('\n\n');
    buffer = blocks.pop() ?? '';
    for (const block of blocks) {
      parseSseBlock(block, { onToken, onDone, onError });
    }
  }
}
```

## 7. 错误与边界处理

### 7.1 统一错误体

后端返回 `ErrorResponse`（6.1）：

```json
{
  "code": "FILE_TOO_LARGE",
  "message": "知识库文件不能超过 20MB",
  "traceId": "abc123",
  "timestamp": "2026-08-10T08:00:00Z"
}
```

前端规则：优先展示 `message`；开发环境可在控制台打印 `traceId` 便于排障。

### 7.2 常见错误码

| code | 场景 | 前端行为 |
|------|------|----------|
| `AUTH_INVALID` | Token 无效 | 跳转登录 |
| `RATE_LIMITED` | 请求或上传过频 | Toast 提示 |
| `QUOTA_EXCEEDED` | 团队 Token 配额用尽 | 对话区提示 |
| `FILE_TOO_LARGE` | 文件超限 | 上传前可预检 size，失败时展示 message |
| `UNSUPPORTED_FILE_TYPE` | 扩展名不允许 | 选择文件时预检 + 失败提示 |
| `LLM_TIMEOUT` 等 | SSE error 事件 | 助手消息区展示错误 |

### 7.3 会话标题

首条用户消息发送后，若 Session 标题仍为「新对话」，自动 `PATCH /sessions/{id}` 将标题设为消息前 30 字（截断加省略号）。

### 7.4 并发与幂等

- 同 Session 流式回复进行中：禁用发送按钮，防止重复提交。
- `clientMessageId` 每次发送生成唯一值，配合后端幂等（6.2）。

## 9. 实现阶段建议

| 阶段 | 内容 | 验收标准 |

## 10. 本地开发

### 10.1 依赖服务

按 `deploy/docker-compose.yml` 启动中间件；控制面运行在 `8080`：

```bash
# 中间件
cd deploy && docker compose up -d

# 控制面（项目根目录按现有 README/Makefile 启动）
# 前端
cd web && npm install && npm run dev
```

浏览器访问 `http://localhost:5173`，API 经 Vite 代理至 `http://localhost:8080`。

### 10.2 生产部署（V2 规划）

- 静态资源构建：`npm run build` → `dist/`。
- 可由 Nginx 托管静态文件，并将 `/api` 反代至 control-plane。
- 或与 control-plane 同域部署，彻底避免 CORS。
