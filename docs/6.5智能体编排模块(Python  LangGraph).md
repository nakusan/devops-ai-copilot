# 6.5 智能体编排模块（Python / ReAct Orchestrator）

> 所属系统：DevOps AI Copilot — 智能面（Python AI Plane）  
> 模块定位：**AI 诊断的「执行引擎」** — Orchestrator 持有 ReAct 工具循环（LLM function calling），调用 RAG / MCP / 分析任务，最终流式合成回答；对外提供 `/internal/v1/chat/stream`  
> 参考业界：OpenAI Assistants / Chat Completions tool calling、Anthropic tool use、Dify Agent 模式

---

## 1. 功能背景与边界

### 1.1 功能背景

单次用户提问在 DevOps 场景下往往不是「直接问 LLM」：

```text
「STATUS_899 是什么？」              → retrieve_knowledge
「当前 DB 连接数正常吗？」            → prometheus_query
「STATUS_899 现在连接数正常吗？」    → 先检索手册，再查监控（多轮）
「你好」                             → 不调工具，直接回答
「刚才那个 heap 分析结果呢？」        → list_analysis_jobs → get_analysis_job
```

**谁调用工具、调几次、参数填什么，由 LLM 决定**，不再用正则路由 / 关键词映射。

编排器与 Java 控制面通过 **HTTP 流式（NDJSON）** 对接（6.2 SSE 终点在 Java）。

### 1.2 模块职责（In Scope）

| 能力 | 说明 |
|------|------|
| ReAct Orchestrator | 规划轮（tools）↔ 执行工具 ↔ 最终流式回答 |
| Tool Registry | OpenAI 兼容 `tools` schema（按 enableRag / enableMcp 裁剪） |
| Tool Executor | `retrieve_knowledge` / MCP / `list|get_analysis_jobs` |
| LLM Client | 规划轮非流式 `complete_with_tools`；最终轮 `stream_chat` 或切片已有 content |
| HTTP API | `POST /internal/v1/chat/stream`、`POST /internal/v1/chat/cancel` |
| 流式事件 | token / citation / **tool** / done / error（NDJSON） |
| Service Token | 仅接受 Java 调用 |
| 取消 | 每轮规划前、工具执行前检查 `cancel_event` |

### 1.3 模块边界（Out of Scope）

| 不属于本模块 | 归属 |
|--------------|------|
| JWT 用户鉴权 | 6.1 Java |
| Message 落库、SSE 对客户端 | 6.2 Java |
| 向量入库管道 | 6.4 Ingest Consumer |
| MCP Server 实现 | 6.6 / 外部 |
| Kafka 消费 | 6.4 / analysis worker |
| Agent CRUD | 6.2 Java |
| Checkpoint / 人机审批 / 多 Agent | V2 |

### 1.5 运行时循环（替代原硬编码 DAG）

```text
messages = system + history + user
tools = build_openai_tools(agent_config)

for round in 1..AGENT_MAX_TOOL_ROUNDS:
    if cancel → error CANCELLED
    turn = complete_with_tools(messages, tools)   # 非流式
    if turn.tool_calls:
        yield tool(start) → execute（可并行）→ yield tool(done)
        若有检索命中 → yield citation
        messages += assistant(tool_calls) + tool results
        continue
    else:
        若有 content → 本地切片推 token（不重复打模型）
        否则 → stream_chat(messages) 无 tools
        break

yield done（intent 由实际调用过的工具推导）
```

**已移除**：Router 正则、关键词 `resolver`、`fan_out` 并行节点、LangGraph 硬编码 DAG、默认 `db_connections`。

同一轮多个 `tool_calls` 由模型一次给出，Executor 内 `asyncio.gather` 并行执行。

## 2. 工具一览

| 工具名 | 条件 | 作用 |
|--------|------|------|
| `retrieve_knowledge` | `enableRag` | 知识库检索；**query 由模型改写** |
| `prometheus_query` | `enableMcp` + prometheus server | 枚举 key 查指标（白名单，见 6.6） |
| `readonly_sql` | `enableMcp` + postgres-readonly | 单条 SELECT |
| `list_analysis_jobs` | 始终 | 列用户最近 N 条分析任务 |
| `get_analysis_job` | 始终 | 按 jobId 取详情；省略 id 则最近 COMPLETED |

工具结果写入 messages 前截断：`TOOL_RESULT_MAX_CHARS`（默认 4000）。

`done.intent` 推导：

| 实际调用 | intent |
|----------|--------|
| 无 | `direct` |
| 仅 retrieve | `rag` |
| 仅 MCP | `tool` |
| retrieve + MCP | `rag_and_tool` |
| 含 list/get analysis | `analysis` |

## 3. 流式协议（对内 NDJSON）

| type | 含义 |
|------|------|
| `token` | 最终答案增量 |
| `citation` | 检索引用（可在工具轮后提前发） |
| `tool` | `{name, status: start\|done, arguments?, success?, error?}` |
| `done` | usage / intent / citations / toolCalls |
| `error` | `{code, message}` |

Java `ChatService` 将 `tool` 转为 SSE `event:tool`；前端展示「正在调用 …」。

## 6. 取消语义

- Java 断 SSE → `POST /internal/v1/chat/cancel` → 进程内 `CancelRegistry` set Event
- Orchestrator：每轮 `complete_with_tools` 前后、工具执行前检查
- LLM stream 循环内检查（与原先一致）
- **已知局限（扩副本前）**：CancelRegistry 是进程内字典；多实例需 Redis 广播（见扩展性评测）

## 8. 验收要点

1. 「你好」不调 retrieve，`done.intent=direct`
2. 模型显式 `prometheus_query` 才查指标；**无默认 db_connections**
3. 可多轮：先 retrieve 再 prometheus，`intent=rag_and_tool`
4. NDJSON 含 `tool` 事件；Java/前端可展示
5. `list_analysis_jobs` + `get_analysis_job` 可指向指定任务
6. 取消可在工具执行前打断
7. `uv run pytest` 在 `LLM_MODE=mock` 下通过
